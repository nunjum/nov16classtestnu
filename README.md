## Proposed Regulation Simulation

A planned section of the demo where a user injects a scenario built from new intelligence about a potential regulation. The section then shows the modeled impact on supply chains and data center design. It ships with a placeholder preset, "Next-Gen Optics Restriction." Students later replace the placeholder data with their own Sayari analysis of real parts.

Every regulatory item carries an evidence tier: `IN_FORCE`, `PROPOSED_BILL`, `REPORTED_DRAFT` or `HYPOTHETICAL`. Proposed or reported items are never presented as law.

**Status:** concept and specification only. The feature is not implemented yet, and this folder contains no demo code. The Sayari-derived values are not yet filled in. Where `SOURCES.md` says UNVERIFIED, the claim has not been confirmed against a primary source.

- [CONCEPT-IDEA.md](CONCEPT-IDEA.md): why anticipatory analysis matters, the evidence-tier principle, the student workflow, example learning questions, and the risks of over-claiming.
- [SPECIFICATIONS.md](SPECIFICATIONS.md): data model, scenario injector inputs, outputs, data center design rules, Sayari integration points with stub fallbacks, proposed file and route changes, test cases and acceptance criteria.
- [SOURCES.md](SOURCES.md): primary-source check for each item in the preset, with URLs and last-verified dates.
